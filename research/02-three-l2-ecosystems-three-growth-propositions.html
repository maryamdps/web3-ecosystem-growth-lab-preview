RESEARCH 02 · ECOSYSTEM STRATEGY

Three L2 ecosystems.
Three growth propositions.

Base, Arbitrum and ZKsync are all connected to Ethereum, but their current product narratives, developer propositions and ecosystem structures create different strategic questions for growth teams.

01 / THE COMPARISON

Same broad category. Different routes to value.

This is a strategic reading of each ecosystem's public documentation and positioning — not a ranking of network performance, market share or user adoption.

01 / BASE

Make on-chain activity feel accessible.

Base's public positioning increasingly connects chain infrastructure with consumer-facing experiences and economic activity.

  • Official messaging spans trading, payments and builders.
  • Base App is positioned around creating, earning, trading, discovering apps and social interaction.
  • Developer distribution and onboarding are explicit parts of its builder proposition.
02 / ARBITRUM

Build infrastructure for financial applications.

Arbitrum presents itself as a finance-native platform supporting applications, tokenisation and configurable dedicated chains.

  • Public docs foreground Arbitrum One, Nova and custom Arbitrum chains.
  • Stylus broadens developer options with Rust, C and C++ alongside Solidity.
  • Docs emphasise configurable execution, data availability, fees and governance.
03 / ZKSYNC

Connect specialised chains through ZK infrastructure.

ZKsync describes an Elastic Network of interconnected chains built with the ZK Stack, using validity proofs and shared interoperability mechanisms.

  • ZKsync Era is described as a ZK rollup.
  • The wider network includes multiple chains and operating modes.
  • Its proposition includes developer tooling and native interoperability between ZKsync chains.

03 / GROWTH IMPLICATIONS

Different propositions call for different GTM emphasis.

Base · Lead with the job to be done

Test consumer and use-case-led entry points: payments, trading, creator tools or a specific app. Explain the outcome first; introduce network mechanics only when they affect the task.

Arbitrum · Lead with trust and application context

For financial use cases, pair product education with clear information on assets, liquidity, chain selection, security assumptions and transaction steps.

ZKsync · Lead with the network mental model

Help builders and users understand what a multi-chain network enables, how chains relate and what interoperability changes in a real workflow.

All three · Make first value observable

Measure the first meaningful product action and subsequent return, not just wallet connections, social engagement or raw transaction volume.

04 / WHAT TO TEST NEXT

Turn positioning into testable questions.

BASE TEST IDEA

Use-case landing pages

Compare a use-case-first entry page with a chain-first explanation. Measure qualified app visits and completed first actions.

ARBITRUM TEST IDEA

Financial product explainers

Test whether a short product-risk-and-process explainer improves users' ability to select a chain and complete a target action.

ZKSYNC TEST IDEA

Interoperability walkthrough

Test a task-based visual guide against a terminology-led guide. Measure task completion, help requests and user comprehension.

These are proposed experiments, not completed campaigns. Before execution, each team would need access to its own product analytics, target users and baseline conversion data.

Primary materials reviewed.
