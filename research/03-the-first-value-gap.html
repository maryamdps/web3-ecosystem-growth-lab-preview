GROWTH EXPERIMENT 01 · ACTIVATION

The first-value gap.
From visit to useful action.

A proposed experiment for a Web3 application that attracts interested visitors but loses some of them before they complete a first meaningful on-chain action.

Proposed experiment · Not yet executed
01 / THE PROBLEM

A connected wallet is not the same as an activated user.

Many Web3 funnels treat wallet connection as the main conversion event. But a connected wallet does not prove that someone understands the product, completes a useful task or intends to return. The experiment focuses on the gap between initial interest and a first product-value event.

Working problem statement

New users may abandon the journey because they do not understand the next step, lack the required asset or network, feel uncertain about signing a transaction, or encounter avoidable setup friction.

02 / HYPOTHESIS

Make the next action obvious — and explain why it is needed.

If first-time visitors receive a task-specific onboarding path that explains the action, requirements, fees and expected outcome before asking them to connect or sign, a greater share should complete the defined first-value event.

Primary hypothesis

A guided, use-case-specific path will increase first meaningful action completion per eligible new visitor compared with the existing onboarding journey.

Secondary hypothesis

Showing network, asset and fee requirements before the wallet prompt will reduce avoidable setup failures and support requests.

03 / EXPERIMENT DESIGN

Change one journey, not the entire product.

01 / DEFINEPick one use caseChoose one app action with clear user value and a measurable completion event.
02 / BASELINEMap current flowReview existing analytics, funnel steps, support questions and user feedback.
03 / DESIGNBuild guided pathExplain outcome, wallet, network, asset, fees and transaction confirmation.
04 / TESTCompare cohortsRandomly assign eligible new users to control and treatment where feasible.
05 / LEARNReview qualityCompare first value, failures, support needs and return behaviour.
The experiment should be run only after defining the product-specific first-value event and confirming that analytics can reliably observe each step. If random assignment is not feasible, use a clearly documented staged rollout and avoid causal claims.
04 / THE TREATMENT

A practical onboarding sequence.

StepWhat the user seesFriction it addresses
1 · OutcomeOne sentence explaining what the user can do and why it may be useful.Unclear value proposition.
2 · RequirementsRequired wallet, network, asset and any relevant prerequisites, shown before the action.Unexpected setup and funding requirements.
3 · Safety contextPlain-language explanation of the permission or transaction being requested, including fees and material risks.Fear of signing something unclear.
4 · Guided actionOne clear next step at a time, with contextual help and recovery guidance for common errors.Decision overload and dead ends.
5 · ConfirmationClear confirmation of what happened, where to view it and what useful next step is available.Uncertainty after the transaction.
05 / MEASUREMENT PLAN

Measure completion, quality and return.

The primary metric should be tied to the app's real value event — not a generic wallet connection. Set the observation window and cohort rules before the experiment begins.

06 / DECISION RULES

Do not optimise conversion at the expense of trust.

Safety before speed

Do not hide fees, permissions, custody details or transaction risks to reduce drop-off.

Quality before volume

Exclude bots, internal testing and suspicious incentive-driven activity from user conversion metrics.

Evidence before claims

Calculate the required sample and test duration from baseline conversion and expected effect. Do not declare a winner from a handful of users.

What would count as a positive result? A credible improvement in first-value completion without worsening failure rates, user confusion, safety incidents or subsequent repeat use. The threshold must be set with the product team before the test — no outcome is assumed here.
